# mold-mol — workstream WS-01

Domain core. The coordinate arena (with optional bonds), PDB/mmCIF and SDF/molfile I/O, the binary arena cache, the pose-table schema and the `Selection` value.
Read [docs/architecture.md](../../docs/architecture.md#core-data-model) first.

## Scope
- **Arena**: struct-of-arrays atoms. `positions: Vec<[f32; 3]>` contiguous and GPU-uploadable as-is; element, residue index, chain index, B-factor as parallel arrays. `PoseId` indexes into it. Coordinates live here and nowhere else.
- **I/O**: wrap `pdbtbx` for PDB and mmCIF read/write into the arena. Handle alternate locations and covalent ligands.
- **SDF / molfile** (`sdf`): our own V2000 + V3000 reader and V2000 writer, no RDKit (product-owner decision 2026-11-27: `geom` and `nodes` must not need `chem`'s RDKit build). One pose per record, bonds into the arena, title + data items returned per record. Chemistry on top (standardisation, stereo) is `chem`'s.
- **Binary arena cache** (`cache`): `save`/`load` an `Arena` in a versioned, checksummed binary format. *When* and *where* to cache is not `mol`'s job.
- **Pose table**: one Polars `DataFrame`, one row per pose, columns in `pose_columns`. Never holds coordinates.
- **Selection**: the value type only. The broadcast bus is in the UI layer.

## Contract (changes go to `main` first, in their own PR)
`PoseId`, `Selection`, `pose_columns`, and the arena's public read API (other crates read positions and per-atom arrays).

## May depend on
std, `pdbtbx`, `polars`, `arrow`, `blake3`; dev: `criterion`, `proptest`. **Never** GPUI, wgpu or an async runtime.

## Design notes
- **Pose layout: full copies.** A pose is one complete complex (receptor + ligand) in one contiguous atom range; poses are appended back to back. Co-folding (Boltz-2) moves the receptor too (hence `pocket_rmsd`), so "receptor once + ligand per pose" would be wrong for this product. Cost at the budget (500 poses × ~3,000 atoms = 1.5 M atoms): positions 18 MB, all per-atom arrays together 34 B/atom ≈ 51 MB. GPU: upload `positions()` once as one buffer; draw a pose with its `atoms` range as base offset/count, or upload just `pose_positions(id)` (a sub-slice, zero copy). If memory ever matters, deduplicate topology (names, elements, residue tables) per pose template; positions stay as they are.
- **Read API for `geom` / `render`**: `Arena::positions() -> &[[f32; 3]]` (also `positions_flat() -> &[f32]`), parallel `elements() -> &[Element]` (`u8` atomic number), `atom_names() -> &[AtomName]` (4 inline bytes), `residue_indices() / chain_indices() -> &[u32]`, `b_factors() / occupancies() -> &[f32]`, `formal_charges() -> &[i8]`; tables `residues()`, `chains()`, `poses()`; `pose_positions(PoseId)`, `pose_of_atom(usize)`. All indices are global (arena-wide), `u32` per atom, like `Selection::atom_mask`. `positions_mut()` edits coordinates in place; topology only grows through `begin_pose` → `PoseBuilder` → `finish` (dropping the builder rolls back).
- **Altloc policy** (`AltLocPolicy`, default `HighestOccupancy`): per residue, never per atom, keep the altloc with the highest mean occupancy (ties: first in file); `First` keeps the first altloc. Atoms without an altloc id are always kept with their file occupancy. Workaround: pdbtbx copies blank-altloc atoms into every conformer and divides their occupancy; `io::pick_conformer` detects and undoes that.
- **What a read keeps**: everything in each model (protein, ligands, waters, ions, H), one pose per model, chains by author id (so a ligand sits in its protein's chain, as in PDB files). `pdbtbx` runs with `only_atomic_coords` so SEQRES does not add atom-less residues. Covalent ligands are kept whole, but `pdbtbx` 0.12 does not parse `LINK`/`struct_conn`, so the bond itself is not stored.
- **Writing**: mmCIF through `pdbtbx`; PDB with our own fixed-column writer, because `pdbtbx::save_pdb_raw` strips leading zeros from every field (`0WN` → `WN`). Fields that don't fit PDB columns are an error ("write mmCIF").
- **Pose table**: `pose_table::SCHEMA` (name + `ColumnType`, canonical order) and `pose_table::empty() -> DataFrame`. Polars is held at 0.53 with no default features: 0.54+ links tokio unconditionally.
- **Bonds: one arena-wide table, global indices, a run per pose.** `Arena::bonds() -> &[Bond]` holds every bond; `Arena::pose_bonds(PoseId) -> Option<&[Bond]>` is the pose's contiguous sub-slice (empty for PDB/mmCIF poses). `Bond { a, b: u32, order: BondOrder }` with **global** atom indices, like every other index in the arena; `Bond::relative_to(pose.atoms.start)` gives pose-local ones. `BondOrder` has geom's variants (`Single, Double, Triple, Aromatic`) plus MDL code conversions. Why: connectivity is topology, so it belongs next to the per-atom arrays (one source of truth, cached with them, never a second copy of coordinates); global indices let `render` build a stick index buffer straight into the one positions buffer, and `geom`/`nodes` index per-pose slices after one subtraction. The per-pose bond ranges live in a private table parallel to `poses` rather than in `Pose` (adding a public field would break a contract struct). Bonds grow only through `PoseBuilder::add_bond` (global indices from `add_atom`; panics outside the pose or on a self-bond; rolled back with the pose).
- **Bond sources, out of scope for now**: mmCIF `struct_conn` / PDB `LINK`/`CONECT` are not read (`pdbtbx` 0.12 does not parse them). Bond **perception** from distances is not done either; `render` has a temporary distance-based guesser, but perception belongs in `mol` long term (follow-up).
- **SDF policy**: one pose per record, chain `L`, one hetero residue `LIG` 1, generated atom names (`C1`, `CL1`: symbol + per-element counter). Title → pose name (blank title → `"<name> record <i>"`); title and `> <field>` data items are returned as strings in `SdfRecord` (they feed the pose table later; the arena holds no metrics). Charges: atom-block code, replaced wholesale by `M  CHG` when present (CTfile rule); V3000 `CHG=`. `D`/`T` read as H, other pseudo-atoms as `Element::UNKNOWN`. Query bond types (5–8), atom lists and unknown versions are `SdfError::Unsupported`. **Per-record errors never abort the file**: `SdfRead { records, errors }`, each error with its 0-based record index and 1-based input line; a failed record leaves nothing in the arena. Only stream I/O errors are `Err`. Duplicate bonds, out-of-range atoms and self-bonds are malformed. Writer: V2000 only, ≤ 999 atoms and bonds (else `IoError::Write`), charges as `M  CHG`.
- **Binary cache format** (`cache`, version 1): 16-byte magic (`cache::MAGIC`, PNG-style: `0x89`, `MOLDARENA`, CR LF, `0x1a`, LF, two zero bytes; catches text-mode mangling), `u32` version, `u64` payload length, 32-byte BLAKE3 of the payload, then 12 tagged, length-prefixed sections in a fixed order (per-atom arrays, residue/chain/pose tables, bonds). Little-endian, `std` + `blake3`, no serde, no `unsafe`. Load verifies magic → version → length → hash, then validates every array length, index and range before building the arena, so neither a corrupt nor a forged-but-rehashed file can panic us or a consumer. **Versioning policy**: any layout change bumps `FORMAT_VERSION`; a reader accepts only its own version (`CacheError::Version`, message says "rebuild the cache"). A cache is derived data, so there is no migration. *When/where* to write it is the caller's (the run-directory cache is WS-04's).
- **Load budget** (`benches/load.rs`, `--release`, Windows dev box, 2026-11-27): 300 poses / 704,400 atoms. mmCIF parse (pdbtbx, 58.8 MB) **2.90 s**; binary cache load (27.2 MB) **27.4 ms**, save 48 ms. The cache leaves ~1.97 s of the 2 s budget to `ui-panels`. `tests/budget.rs` asserts < 500 ms.
